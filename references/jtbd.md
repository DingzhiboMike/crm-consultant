# JTBD — Jobs-to-be-Done в CRM-контексте

Читать при: проектировании триггерных коммуникаций, определении activation event, создании велком-серий, разработке реактивационных механик.

---

## Суть для CRM

Клиент не «использует продукт» — он **нанимает** его для выполнения конкретной работы. Коммуникация, которая не помогает клиенту выполнить его работу — игнорируется или раздражает.

Практический вывод: прежде чем проектировать любую коммуникацию, ответь на вопрос «какую работу клиент пытается выполнить в этот момент?»

---

## Три уровня работ

### Функциональный уровень
Конкретное действие, которое нужно выполнить.
- «Выставить счёт подрядчику»
- «Проверить статус платежа»
- «Добавить сотрудника в систему»

### Эмоциональный уровень
Что клиент хочет почувствовать после выполнения работы.
- Уверенность (что сделал правильно)
- Контроль (знаю что происходит)
- Спокойствие (ничего не потеряется)

### Социальный уровень
Как клиент хочет выглядеть перед другими.
- «Я профессионал, который использует современные инструменты»
- «Я не подведу команду / партнёра»
- «Я принял правильное решение при выборе продукта» (снижение когнитивного диссонанса)

**Применение в CRM:** Велком-письмо должно решать функциональную работу (помочь сделать первый шаг), но тон и формулировки — апеллировать к эмоциональному уровню («вы в надёжных руках»).

## Как выявить JTBD для CRM-механики

### Метод 1: Анализ точки регистрации / первого контакта
Что происходило в жизни клиента прямо перед тем, как он пришёл? Это и есть «найм» продукта.

Вопросы для исследования:
- «Что произошло, что вы начали искать решение?»
- «Что вы делали раньше вместо этого?»
- «Что стало последней каплей, что заставила вас начать пробовать?»

### Метод 2: Анализ отказов
Почему клиент уходит (или не активируется)? Обычно потому что продукт не выполнил нужную работу.

Exit interview вопросы:
- «Какую задачу вы хотели решить с нашим продуктом?»
- «Что пошло не так?»
- «Что вы используете вместо нас?»

### Метод 3: Сегментация по JTBD (вместо демографии)
Вместо «ИП» vs «ООО» — «те, кто нанимает продукт для автоматизации рутины» vs «те, кто нанимает для контроля над командой».

## JTBD по стадиям Lifecycle

### Onboard — самый критичный момент
Клиент нанял продукт для конкретной работы. Онбординг должен помочь ему выполнить эту работу как можно быстрее.

**Ошибка:** Велком-письмо рассказывает о компании и фичах → клиент не понимает как это связано с его работой.

**Правильно:** Велком-письмо начинается с работы клиента: «Вы зарегистрировались — скорее всего, чтобы [выполнить работу X]. Вот первый шаг.»

### Engage — формирование привычки
На этой стадии JTBD расширяется: клиент ищет, как делать свою работу быстрее / лучше / с меньшим усилием.

**Механика:** Образовательный контент, который показывает как продукт помогает выполнить смежные работы.

### Retain — сохранение relevance
JTBD клиента меняется с ростом бизнеса. Риск оттока часто в том, что продукт перестал соответствовать новой работе.

**Механика:** QBR / check-in с вопросом «как изменились ваши задачи?», мониторинг новых use-cases.

### Expand — новые работы
Upsell работает, когда клиент «нанимает» продукт для новой работы — но узнаёт что продукт это умеет.

**Механика:** Триггер при достижении лимита + объяснение новой работы, которую решает следующий тариф.

## Practical templates

### Формула велком-письма через JTBD
```
Тема: [Конкретный результат, который получит клиент]

Тело:
Вы зарегистрировались — значит, вам нужно [работа].

Первый шаг: [конкретное действие, ведущее к activation event]

[CTA → действие]

Это займёт [X минут]. После этого вы сможете [результат].
```

### Формула реактивационного письма через JTBD
```
Не «мы скучаем по вам» →
«Вы регистрировались, чтобы [работа]. Мы добавили [новое], которое делает это проще. Посмотрите: [конкретный пример]»
```
